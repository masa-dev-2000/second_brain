## 概要
会話やブレストをリアルタイムで録音し、ボタンひとつ押すだけで、その内容からプロダクトモック(プロトタイプ)を生成するためのプロンプトを出力するツール。

## 背景・きっかけ
- アイデア出しの会話中に出た内容を、後からまとめてモック化するのは手間がかかる
- 録音 → 文字起こし → 要件整理 → モック作成指示、という流れをワンアクションに圧縮したい

## メモ
- フロー案: 録音(リアルタイム文字起こし)→ 会話から要件・機能を抽出 → v0 / Claude / Figma Make などに渡せるモック作成プロンプトを整形して出力
- 出力先の候補: クリップボードコピー、Markdownファイル、直接生成AIツールへ送信
- 技術要素の候補:
  - 音声認識: Whisper系のストリーミング文字起こし
  - 要約・プロンプト整形: LLM
  - UI: 録音ボタン+「モックプロンプト生成」ボタンだけのミニマルな画面
- 拡張アイデア: 会議終了時に自動で複数案のプロンプトを出す、過去録音からの再生成

## 気づき(2026-06-10)
- 実装はシンプルでいける: リアルタイム録音した音声(または文字起こしテキスト)をAPIでLLMに投げるだけで成立する
- 音声対応モデル(例: Claude / GPTの音声入力、Whisper API)を使えば、文字起こしと要件抽出を1回のAPI呼び出しにまとめられる可能性もある
- まずは「録音 → API → プロンプト出力」の最小構成でプロトタイプを作るのが良さそう

## 調査メモ: Meet等へのプラグイン化と既存ツール(2026-06-10)

### Google Meetへの組み込みは可能
- **Meet Add-ons SDK**: Meetのサイドパネル/メインステージに自作アプリを埋め込める。ただしUI埋め込みのみで、会議音声へのアクセスは不可
- **Meet Media API**(Developer Preview): 会議の生音声・映像ストリームにリアルタイムアクセス可能。ただしSDKなしでWebRTCスタックを自前実装する必要があり、ホストの承認も必要でハードルは高め
- 現実的な代替ルート:
  - Chrome拡張でタブ音声をキャプチャ(Tactiq等がこの方式)
  - 会議に参加するボット方式(Fireflies/Otter等。Recall.aiのようなボットAPIを使えば楽)
  - ローカルでシステム音声をキャプチャ(Meetily等。会議ツール非依存で最も簡単)

### 既存ツールの状況
- リアルタイム文字起こし+要約は既にコモディティ: Otter.ai、Tactiq、Fireflies、Krisp、Read.ai、Meetily(OSS・ローカル完結)など多数
- ただし「会話からプロダクトモック作成プロンプト(v0/Figma Make向け)を出力する」ものは見当たらず → **この出力レイヤーが差別化ポイント**
- 既存の文字起こしツールの出力をLLMに流すだけでも実現できるので、最小構成ならChrome拡張 or ローカルアプリ+LLM APIが手軽
