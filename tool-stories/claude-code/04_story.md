# ストーリー4：「脆弱性の地雷原」
副題 ── 中村亮と本番リリース前夜のセキュリティ監査 ──

## 登場人物
中村亮・34歳・セキュリティエンジニア（受託開発会社勤務）。
ペネトレーションテストの経験3年。チームの開発コードのセキュリティレビューも担当しているが、一人で全コードを追うには限界を感じていた。

## 問題
新規 SaaS プロダクト（B2B 顧客管理ツール）のリリースが2週間後に迫っている。バックエンドは Node.js / Express、フロントエンドは React。コードベースは約 18,000 行。中村が手動でレビューするには4〜5日かかるが、ほかにも並行タスクが山積みだった。OWASP Top 10 への対応状況を確認するだけでも1日仕事になる。

## 出会い
Anthropic が公開した Claude Code Security Review 機能と GitHub Actions 連携のブログ記事を読んで試験導入を決めた。

## 実装
```bash
# コードベース全体のセキュリティスキャン
$ claude "このリポジトリの OWASP Top 10 観点で脆弱性を
  スキャンして。重要度 High / Medium / Low で分類して"

# 特定箇所の深掘り
$ claude "src/api/auth/ の JWT 実装を詳しく見て。
  トークン検証・有効期限・ refresh token の
  セキュリティ問題を指摘して"

# 修正コード生成
$ claude "特定した SSRF の脆弱性を修正して。
  ホワイトリスト方式で外部URL呼び出しを制限するコードを書いて"
```

Claude は SQL インジェクション・XSS・不適切な認証・機密データの平文保存など17件の問題を検出し、重要度別に整理したレポートを Markdown で出力した。

## 壁
Claude が「High」と判定した問題の一つ、ユーザー入力をそのまま `child_process.exec` に渡しているコマンドインジェクションの修正コードを生成したが、生成されたコードが既存の引数エスケープ処理と二重になり、正常なコマンドも弾いてしまうバグが混入した。

## 解決
「既存のサニタイズ処理と競合しないように修正して。既存コードを読んでから提案して」と指示し直すと、Claude は既存の `validator.js` の処理を確認した上で、重複しない形での修正版を提案した。

## 結果
| 指標 | Before | After |
|------|--------|-------|
| セキュリティレビュー所要時間 | 4〜5日（予定） | 6時間 |
| 検出脆弱性 | - | 17件（High:3, Medium:9, Low:5） |
| 修正完了 | - | High:3件 全修正、Medium:7件修正 |
| リリース判断 | 不安なまま予定通り | 確認済みの状態でリリース |

## 使った機能
| 機能 | 用途 |
|------|------|
| OWASP Top 10 スキャン | 脆弱性の網羅的検出 |
| 重要度分類レポート | 対応優先度の判断 |
| 修正コード生成 | 脆弱性パッチ作成 |
| 既存コード読み込み | 競合しない修正の確認 |
