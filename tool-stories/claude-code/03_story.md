# ストーリー3：「テストゼロからの出発」
副題 ── 佐藤健一と「怖くて触れないコード」の克服 ──

## 登場人物
佐藤健一・27歳・フロントエンドエンジニア（スタートアップ勤務2年目）。
React を中心に開発しているが、テストをちゃんと書いた経験はほぼゼロ。「テストは書くべきだと知っているが、どこから手を付けていいかわからない」と思い続けて2年が経った。

## 問題
チームの EC サイトには決済フロー・カート・会員管理など重要なコンポーネントが 80 以上あるが、テストカバレッジは 3%。デプロイのたびにリグレッションが1〜2件発生しており、先月は本番でカートに商品が追加できないバグが2時間放置された。CTOから「リリース前にカバレッジ 60% を達成してほしい」と指示が来た。

## 出会い
Twitter（現X）のタイムラインで「Claude Code にテスト生成させたら1日でカバレッジが爆上がりした」という投稿を見て試してみた。

## 実装
```bash
# まず既存コンポーネントを分析
$ claude "src/components/Cart/ の全コンポーネントを分析して、
  テストすべき重要なユーザー操作と境界値を洗い出して"

# テスト生成
$ claude "CartItem.tsx の Vitest + Testing Library テストを
  全パターン書いて。商品削除・数量変更・在庫切れ表示も含めて"

# カバレッジ確認しながら進める
$ claude "現在のカバレッジレポートを見て、
  まだテストされていない重要なパスを教えて"
```

Claude は各コンポーネントのプロパティ一覧・状態遷移・エッジケースを表形式で整理してから、`describe` ブロックを意味のある単位で分割したテストコードを生成した。

## 壁
CartSummary コンポーネントのテストで、モックした決済 API が非同期で応答するケースを Claude が同期的に扱ってしまい、テストが常に成功する（= 意味のないテスト）状態になっていた。佐藤がしばらく気づかなかったのが問題だった。

## 解決
「このテスト、本当に決済エラー時を検証できてる？」と Claude に確認させると、「`await` が抜けていて常に pending 状態でパスしています」と自己診断。`waitFor` と `act` を適切に使った修正版を提示した。

## 結果
| 指標 | Before | After（2週間後） |
|------|--------|-----------------|
| テストカバレッジ | 3% | 67% |
| テストファイル数 | 4 | 89 |
| デプロイ後リグレッション | 月1〜2件 | 0件（4週間） |
| テスト作成速度 | 1コンポーネント/日 | 6〜8コンポーネント/日 |

## 使った機能
| 機能 | 用途 |
|------|------|
| コンポーネント解析 | テスト対象の洗い出し |
| Vitest / Testing Library テスト生成 | テストコード自動作成 |
| カバレッジレポート読み込み | 未テスト箇所の特定 |
| 非同期テスト修正 | waitFor/act の適切な使い方 |
