# ストーリー8：「7つのAPIをつなぐ」
副題 ── 小林達也と連携地獄からの脱出 ──

## 登場人物
小林達也・33歳・フリーランスエンジニア。
受託開発を中心に活動。「API 連携は得意だが、毎回ドキュメントを読む時間が膨大」と感じていた。今回初めて fintech 領域の案件に入り、各種決済・認証 API に不慣れだった。

## 問題
ある決済サービス事業者のシステム統合案件を受注。Stripe・SendGrid・Twilio・Auth0・Firebase・Plaid・Slack の7つのサービスを一つのバックエンドに統合する必要があった。各 API の仕様書を読むだけで1週間かかる見込みで、納期は3週間後。小林一人でこなすには日程的にギリギリだった。

## 出会い
「API の統合が得意」という Claude Code のレビューを読んで、まず Stripe の統合から試してみた。

## 実装
```bash
# API 統合コードの生成
$ claude "Node.js / TypeScript で Stripe の決済フローを実装して。
  サブスクリプション・Webhook・返金処理も含めて。
  エラーハンドリングも丁寧に書いて"

# 複数サービスの連携
$ claude "決済完了後に SendGrid でメール・Twilio で SMS を
  並列送信して、Firebase に記録する一連のフローを書いて"

# テスト環境の構築
$ claude "Stripe の test モードで全シナリオを網羅する
  integration テストを書いて。失敗ケースも含めて"
```

Claude は各 API の最新仕様を把握しており、`stripe.webhooks.constructEvent` の署名検証や Plaid の OAuth フローなど、ドキュメントを読まないと気づかない実装の細かい点まで考慮したコードを生成した。

## 壁
Auth0 と Firebase の認証が二重になるシステム設計で、トークンの検証順序に矛盾が発生した。Auth0 の JWT を Firebase Functions で検証しようとしたところ、公開鍵の取得タイミングで競合状態が起き、断続的な認証失敗が発生した。

## 解決
「Auth0 と Firebase の認証を共存させるベストプラクティスを教えて。競合状態を避ける実装を提案して」と質問すると、Claude は「Auth0 をプライマリ、Firebase は Custom Token に変換する単方向アーキテクチャ」を提案し、実装コードも添えた。

## 結果
| 指標 | 見積もり | 実績 |
|------|---------|------|
| API ドキュメント読解時間 | 1週間 | 2日（Claude に質問しながら） |
| 統合実装期間 | 2.5週間 | 1.5週間 |
| 統合テスト数 | 計画20件 | 実際 63件生成 |
| 納品クオリティ | 標準 | クライアントから「想定以上」と評価 |

## 使った機能
| 機能 | 用途 |
|------|------|
| 各 API の実装コード生成 | 統合ボイラープレートの削減 |
| Webhook 検証実装 | Stripe セキュリティ要件の充足 |
| 並列処理フロー設計 | マルチサービス連携 |
| 競合状態の診断と修正 | 認証フローの安定化 |
