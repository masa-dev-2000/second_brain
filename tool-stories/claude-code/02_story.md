# ストーリー2：「Excelからの脱出」
副題 ── 山本あかりと売上集計地獄からの解放 ──

## 登場人物
山本あかり・32歳・マーケティングプランナー（食品メーカー勤務）。
コードは書いたことがなく、Python は「ヘビ？」レベル。毎週月曜日は朝8時から Excel で売上データを手作業で集計する作業が2〜3時間かかっていた。

## 問題
全国15店舗のPOSデータが CSV で送られてくるが、フォーマットが店舗ごとにバラバラ（文字コード・日付形式・列順がすべて異なる）。毎週 150 件前後のファイルを VLOOKUP と手コピペで統合し、週次レポートを作成している。作業ミスが月2〜3件発生しており、先月は誤集計で部長に報告したデータを翌日訂正するという事態が起きた。

## 出会い
社内の DX 勉強会で Claude Code のデモを見た。「コードが書けなくてもいい」という説明に半信半疑で自分の PC にインストールしてみた。

## 実装
```bash
# まず一つのCSVを見せて状況を説明
$ claude "この CSV ファイルを見てください。
  毎週こういうファイルが15店舗から150件届きます。
  全部まとめて売上合計・店舗別・商品別に集計する
  Python スクリプトを作ってください"

# テスト実行
$ claude "sales_merge.py を実行して、
  結果を Excel ファイルに出力してください"

# 自動化
$ claude "毎週月曜9時に自動実行する設定も作って。
  完了したら Slack に通知を飛ばしてほしい"
```

Claude は各 CSV の文字コードを自動判定し、日付形式を統一する前処理を組み込んだスクリプトを生成。さらに店舗名の表記揺れ（「東京店」「東京支店」「TOKYO」など）を辞書で正規化する処理も提案してくれた。

## 壁
スクリプトを走らせると、ある店舗だけ文字化けして商品名がすべて「???」になった。山本にはエラーの意味がわからず、パニックになった。

## 解決
エラー画面のスクリーンショットをそのまま Claude に見せると「CP932 と UTF-8 BOM の混在が原因です。該当ファイルだけ自動検出する分岐を追加します」と即座に修正コードを提示。山本はコードを読まずともコピペするだけで解決できた。

## 結果
- 毎週月曜の手作業 **2〜3時間 → 0時間**（完全自動化）
- 集計ミス **月2〜3件 → 0件**
- 月曜の朝にレポートが Slack に自動投稿されるようになり、チームの反応も上々
- 山本は空いた時間をキャンペーン企画に充て、翌四半期に新商品施策を1本立案

## 使った機能
| 機能 | 用途 |
|------|------|
| CSV 解析・前処理スクリプト生成 | 複数フォーマットの統合 |
| 文字コード自動判定 | 文字化け防止 |
| cron 設定 | 定期自動実行 |
| Slack Webhook 連携 | 完了通知 |
