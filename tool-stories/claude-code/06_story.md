# ストーリー6：「VBから現代へ」
副題 ── 伊藤浩二と20年前のシステムとの決別 ──

## 登場人物
伊藤浩二・45歳・システムアーキテクト（中堅製造業の情報システム部門）。
入社23年目。自分が20代のときに作った VB6 の生産管理システムが今もメインで動いており、「あのコードを絶対に若い人に見せたくない」と密かに思っている。

## 問題
VB6 で書かれた生産管理システム（約 35,000 行）のサポート終了問題が表面化。Visual Basic 6 の開発環境は Windows 11 で動作しないため、新しい PC に移行できない社員が出始めた。Python + FastAPI への移行を決定したが、VB6 コードを読める若手エンジニアが社内にゼロ。移行見積もりは外部委託で 1,800 万円と提示された。

## 出会い
外部委託の見積もりに衝撃を受けた伊藤が、まず一部だけ Claude Code で試してみることにした。「失敗しても外注するだけ」と腹を括った。

## 実装
```bash
# VB6 コードの解析
$ claude "この VB6 のコードを解析して、ビジネスロジックを
  日本語で説明して。データフローも図示して"

# Python への変換
$ claude "この VB6 モジュール（在庫計算部分）を
  Python 3.12 / FastAPI に変換して。
  変数名は意味が分かるものに変えて"

# 変換後の整合性確認
$ claude "変換前の VB6 コードと変換後 Python コードで
  同じ入力に対して同じ出力が出るかテストを書いて確認して"
```

Claude は VB6 の `Dim`・`Set`・`GoTo`・`On Error Resume Next` などを正確に解釈し、等価な Python コードに変換。さらに「このコメントは当時の消費税率 5% を前提にしています。現在のロジックは間違っている可能性があります」という注釈も添えた。

## 壁
VB6 特有の `Integer` 型（16ビット、最大 32,767）を Python の `int` に変換したところ、大量発注時の計算で桁あふれを起こしていた古いバグが Python では発現しなくなった。一見「修正された」ように見えたが、20年間のデータが桁あふれを前提に蓄積されていることに後から気づいた。

## 解決
「VB6 の Integer と Python の int の動作差異を洗い出して、データ整合性への影響を評価して」と指示。Claude は過去データの修正スクリプトと、移行時の整合性チェッカーを同時に生成した。

## 結果
| 指標 | 外注見積もり | Claude Code 実績 |
|------|------------|----------------|
| 費用 | 1,800万円 | 約 40万円（人件費換算） |
| 期間 | 18ヶ月 | 6ヶ月 |
| 移行完了率 | — | 95%（残5%は手動対応） |
| コード行数 | VB6: 35,000行 | Python: 14,000行 |

## 使った機能
| 機能 | 用途 |
|------|------|
| VB6 コード解析・説明 | ビジネスロジックの把握 |
| クロス言語変換 | VB6 → Python 変換 |
| 等価性テスト生成 | 変換前後の動作一致確認 |
| 型差異分析 | データ整合性リスクの評価 |
