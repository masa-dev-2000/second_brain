# ストーリー7：「深夜のバグ探偵」
副題 ── 高橋莉子と本番障害の72時間 ──

## 登場人物
高橋莉子・29歳・SRE（Site Reliability Engineer）。
ECサービスを運営するスタートアップ勤務。オンコール担当として深夜のアラート対応も行っている。「障害対応中の思考力の劣化が怖い」と常日頃から感じていた。

## 問題
ブラックフライデーセール期間中、午前2時にアラートが鳴った。特定の商品ページへのアクセスで 500 エラーが断続的に発生。ログには `NullPointerException` が出ているが、ステージング環境では再現せず、原因不明のまま30分が経過。セール中のため売上損失が刻々と積み上がっていた。

## 出会い
高橋は以前から Claude Code をデバッグのペアプログラマーとして使っていた。深夜の焦りの中、ログをコピーしてターミナルを開いた。

## 実装
```bash
# ログを貼り付けてトリアージ
$ claude "このエラーログを解析して。
  500エラーが特定商品だけで起きる理由を仮説立てて"

# 仮説検証
$ claude "product_id=4821 の商品データが
  他の商品と何が違うか DB を調べるクエリを書いて"

# 原因特定後の修正
$ claude "null チェックが抜けている箇所を修正して。
  同じパターンが他のコードにもないか全部検索して"
```

Claude はログのスタックトレースを読み、「`product.variants` が null の場合の処理が欠けている。商品ID 4821 は variants が空の特殊商品の可能性が高い」と5分で仮説を立て、確認クエリを提示した。

## 壁
DB クエリを実行すると確かに variants が null だったが、「なぜ今日だけ 500 になったのか」が分からない。同じ条件の商品は1週間前からあったはずだった。高橋は「原因特定したけど説明できない」という状態になり、上司への報告もできなかった。

## 解決
「今日だけ発生した理由を調べて。デプロイ履歴やコードの差分も見て」と指示すると、Claude が git log を確認し、「本日 18:30 のデプロイで variants の lazy loading から eager loading に変更されており、そのタイミングで null が顕在化した」という根本原因を特定した。

## 結果
| 指標 | 過去の障害（平均） | 今回 |
|------|-----------------|------|
| 初動調査〜原因特定 | 90分 | 22分 |
| 障害継続時間 | 3時間 | 45分 |
| 報告書作成 | 翌日 2時間 | 同夜 30分（Claude が下書き） |
| 再発防止策 | 数日後 | 翌朝の PR で完了 |

## 使った機能
| 機能 | 用途 |
|------|------|
| ログ解析・仮説生成 | 障害原因の絞り込み |
| DB クエリ生成 | データ確認の自動化 |
| git log / diff 解析 | デプロイとの因果関係特定 |
| null チェック修正 | パターン横断修正 |
