# ストーリー8：「SEO記事の量産術」
副題 ── 伊藤 彩、1本8時間の作業を1時間に縮めた話 ──

## 登場人物
伊藤 彩（いとう あや）・27歳・フリーランスのコンテンツライター。  
月に20本のSEO記事を1人で執筆している。クライアントは3社で、月収は安定しているが  
作業時間が月180時間を超えており、「仕事しすぎ」が慢性化していた。

## 問題
SEO記事1本の制作フロー：キーワード調査（1時間）→ 競合記事リサーチ（2時間）→  
構成案作成（1時間）→ 執筆（3時間）→ 校正（1時間）= 合計8時間。  
20本で160時間。残りの20時間で請求書処理・クライアント対応・自己啓発をこなす毎日だった。  
単価を上げたいが、時間的に受注を増やせずジレンマを感じていた。

## 出会い
同じフリーランスのコミュニティで「OpenClaw でリサーチと構成を自動化している」という話を聞いた。  
「最初は『AIに書かせるのは手抜き』という抵抗感があった」と彩は正直に話す。

## 実装
```bash
openclaw onboard
# ブラウザ + ファイルシステム + Slack統合
```

```markdown
# SOUL.md（SEOリサーチエージェント）
あなたはSEOコンテンツのリサーチ・構成担当アシスタントです。

指定されたキーワードに対して：
1. 検索上位10記事のタイトル・見出し・文字数を一覧化する
2. 共通して取り上げられているトピックを抽出する
3. 上位記事が触れていない「抜け漏れトピック」を見つける
4. 推奨構成（H1/H2/H3）を作成する
5. 参考になる統計・データのURLを5件リストアップする

完了したらMarkdownファイルで保存し、Slackに通知する。
```

```bash
# 使い方：Slackに送るだけ
「リサーチお願いします：[キーワード]」
```

## 壁
競合記事の中に「JavaScriptで動的にコンテンツが読み込まれるサイト」が多く、  
OpenClaw のブラウザがページを開いても肝心な本文が取得できないケースが全体の30%あった。  
結果として、構成案に「本来含めるべきトピック」が欠落した状態で出力されていた。

## 解決
「ページの読み込み完了を5秒待ってからスクロール・取得する」という手順を  
`SOUL.md` の操作手順に明示的に追記した。  
さらに取得できなかったURLは別リストに出力し、彩が手動確認できる仕組みにした。

## 結果

| 指標 | Before | After |
|------|--------|-------|
| 記事1本あたりの作業時間 | 8時間 | 約1時間（執筆と最終確認のみ） |
| 月間作業時間 | 180時間 | 約50時間 |
| 月間対応可能本数 | 20本 | 60本（理論値） |
| Googleでの順位到達期間 | 平均8〜12週 | 平均4〜6週（リサーチ精度向上による） |

「仕事を減らしたのに、品質が上がったという矛盾が起きている」

## 使った機能

| 機能 | 用途 |
|------|------|
| ブラウザ操作 | 競合記事の自動クローリング |
| ファイル出力 | Markdown形式の構成案保存 |
| Slack統合 | タスク指示と完了通知 |
| 永続メモリ | クライアントごとのNGキーワード・トーン記憶 |
| SOUL.md 品質ルール | リサーチ手順と出力フォーマット定義 |
