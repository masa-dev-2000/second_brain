# ストーリー1：「メール地獄からの脱出」
副題 ── 田中 恵、受信トレイ4,300通との戦い ──

## 登場人物
田中 恵（たなか めぐみ）・34歳・ITスタートアップのマーケティングマネージャー。  
毎朝9時の始業と同時に受信トレイを開くのが憂鬱になっていた。  
製品リリース後から購読解除の手間が追いつかず、未読メールが慢性的に4,300通を超えていた。

## 問題
1日平均120通の受信メール。そのうち読む価値があるのは推定15通以下。  
返信が必要なメールを見逃して重要顧客を怒らせたことが月に2〜3件発生していた。  
「受信トレイのトリアージ」だけで1日1.5時間を消費している現状があった。

## 出会い
社内のエンジニアから「OpenClaw を使えばメールを自分の代わりに仕分けてくれる」と聞いたのがきっかけ。  
「またAIツールか」と思いつつ、試しに週末の2時間でセットアップしてみた。

## 実装
```bash
npm install -g openclaw@latest
openclaw onboard --install-daemon
```

`SOUL.md` に役割を定義し、`USER.md` に自分の優先ルールを記載：

```markdown
# SOUL.md
あなたはメールを管理するアシスタントです。
重要度を「緊急/通常/不要」の3段階で分類してください。

# USER.md
- 顧客 / パートナー企業からのメールは必ず「緊急」に分類
- ニュースレターと広告メールは自動アーカイブ
- 返信草稿が必要なものはSlackで通知
```

Gmailと接続後、cronで30分ごとの自動処理を設定した。

## 壁
最初の夜、OpenClaw が全社アナウンスメールを「不要」と判断して自動アーカイブし続けた。  
翌朝、重要な組織変更の通知を見逃していたことに気づき、恵は青ざめた。  
`SOUL.md` の分類ルールが曖昧すぎたのが原因だった。

## 解決
`USER.md` に「`@company-domain.com` ドメインからのメールは必ず『通常』以上に分類する」というルールを1行追加。  
さらに「不確かな場合は自動アーカイブせずSlackで確認を求める」という安全策も書き添えた。  
その後は誤分類がゼロになった。

## 結果

| 指標 | Before | After |
|------|--------|-------|
| 受信トレイ未読数 | 4,300通 | 常時50通以下 |
| メール処理時間 | 1日1.5時間 | 1日15分 |
| 重要メール見逃し | 月2〜3件 | 月0件 |
| 返信までの平均時間 | 8時間 | 2時間 |

「受信トレイを開くのが、怖くなくなりました」と恵は言った。

## 使った機能

| 機能 | 用途 |
|------|------|
| SOUL.md / USER.md | 分類ルールと優先基準の定義 |
| Gmailチャンネル統合 | メール受信・アーカイブ・ラベル付け |
| cronスケジューリング | 30分ごとの自動処理 |
| Slack通知 | 確認が必要なメールのアラート |
