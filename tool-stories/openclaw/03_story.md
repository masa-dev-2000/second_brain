# ストーリー3：「契約書1万件の壁」
副題 ── 中村 法子、10年分の文書を3日で整理した話 ──

## 登場人物
中村 法子（なかむら のりこ）・41歳・中堅製造業の法務担当。  
法務部は自分ひとり。契約書の管理はExcelと紙のファイルキャビネットという旧来の体制だった。  
「あの契約、更新期限いつだっけ？」という問い合わせが週に10件以上来ていた。

## 問題
過去10年間に締結した契約書が約10,200件、PDFとスキャン画像で保存されていた。  
契約期限の検索に平均25分かかっており、期限切れの見落としが年に3〜4件あった。  
弁護士事務所への依頼費用として年間240万円が発生していたが、その大半が単純な検索作業だった。

## 出会い
法務系AIのセミナーで「OpenClaw にファイルを読み込ませると契約書を検索できる」という話を聞いた。  
帰りの電車の中でスマートフォンからドキュメントを読んで、「これなら自分でもできる」と直感した。

## 実装
```bash
openclaw onboard
# ファイルシステムツールを有効化
# ドキュメントフォルダをワークスペースにマウント
```

```markdown
# SOUL.md
あなたは契約書管理の専門アシスタントです。
PDFを読み込み、以下を抽出してSQLiteに登録してください：
- 契約相手名
- 契約種別（売買/業務委託/NDA/賃貸借など）
- 開始日・終了日・自動更新条項の有無
- 特記事項

終了日が60日以内の契約は毎朝メールで通知してください。
```

3日間かけてOpenClawが全10,200件のインデックスを自動生成した。

## 壁
スキャン画像の品質が悪いPDFが約800件あり、文字認識が失敗して「不明」として登録され続けた。  
特に10年以上前の書類はインクが薄く、AIが読み取れない箇所が多かった。

## 解決
「不明」タグが付いたファイルだけをリストアップするよう指示し、  
上位200件を優先的に手動で確認するリストをOpenClawに生成させた。  
「全部完璧にしようとするより、リスクの高いものから直す」という発想の転換が突破口だった。

## 結果

| 指標 | Before | After |
|------|--------|-------|
| 契約書検索時間 | 平均25分 | 平均30秒 |
| 期限切れ見落とし | 年3〜4件 | 年0件 |
| 弁護士への依頼費用 | 年240万円 | 年80万円（約67%削減） |
| インデックス済み契約書 | 0件 | 9,400件（残り800件は進行中） |

## 使った機能

| 機能 | 用途 |
|------|------|
| ファイルシステム統合 | PDFの一括読み込みとテキスト抽出 |
| SQLiteメモリ | 契約情報のデータベース管理 |
| cronスケジューリング | 期限60日前の自動アラート |
| メール通知 | 更新期限の毎朝通知 |
| SOUL.md 抽出定義 | 契約書から取得する項目の指定 |
