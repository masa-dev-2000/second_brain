# ストーリー4：「朝のブリーフィング」
副題 ── 佐藤 健一、毎朝7時に届く"知らないはずのニュース" ──

## 登場人物
佐藤 健一（さとう けんいち）・38歳・SaaS系スタートアップのCEO。  
毎朝6時に起床し、シャワーを浴びながらヘッドセットで音声メモを聞く習慣がある。  
競合動向・規制情報・資金調達ニュースを追うために、RSSフィードを80件登録していたが、  
消化しきれず9割は未読のまま溜まり続けていた。

## 問題
意思決定に必要な情報収集に毎朝45分かかっていた。  
競合他社が新機能をリリースしてから自分が気づくまで平均3日のラグがあり、  
2度ほど「もっと早く知りたかった」重要情報を見逃していた。  
「読むべきものと読まなくていいものの仕分けが一番しんどい」と健一は言っていた。

## 出会い
投資家との会食で「OpenClaw で毎朝ブリーフィングを自動生成している」という話を聞いた。  
翌日の夜に自分でも試してみることにした。

## 実装
```bash
openclaw onboard
# チャンネル：Slack + iMessage
# ブラウザツール有効化
```

```yaml
# cron: 毎朝6:55
schedule: "55 6 * * *"
task: |
  以下のソースを確認し、本日のブリーフィングを生成してください：
  - 競合A/B/Cの公式ブログとリリースノート
  - TechCrunch・The Informationの最新記事
  - 業界キーワード「SaaS / AI agent / データ規制」のGoogleニュース
  
  形式：
  1. 今日知っておくべき3件（各3行以内）
  2. 競合動向サマリー
  3. 今週のアクション提案
  
  7:00までにSlackとiMessageに送信してください。
```

## 壁
最初の1週間、ブリーフィングの内容が「表面的すぎる」と感じた。  
「A社が新機能をリリースした」とは書いてあるが、「それが自社にとって脅威かどうか」の判断がなかった。  
OpenClaw はファクトを並べるが、戦略的インサイトを出してはいなかった。

## 解決
`SOUL.md` に健一のビジネスコンテキストを追加した。  
自社のICP（理想顧客プロフィール）・主要競合の強みと弱み・現在の四半期目標をドキュメントとして書き込んだ。  
コンテキストが増えたことで、「これは競合に有利に働く」「このニュースは無視してよい」という判断が出るようになった。

## 結果

| 指標 | Before | After |
|------|--------|-------|
| 朝の情報収集時間 | 45分 | 5分（読むだけ） |
| 競合情報認知ラグ | 平均3日 | 当日 |
| 未読RSS件数 | 80件中72件未読 | 廃止（OpenClawに統合） |
| 経営判断のスピード | ─ | 主観的に「2倍速くなった」と評価 |

「7時にiMessageが来る。これが来ないと1日が始まらない体になってしまった」

## 使った機能

| 機能 | 用途 |
|------|------|
| ブラウザ統合 | ニュースサイト・ブログの自動巡回 |
| cronスケジューリング | 毎朝6:55の自動実行 |
| Slack / iMessage 通知 | ブリーフィングの配信 |
| SOUL.md ビジネスコンテキスト | 戦略的判断の根拠となる情報提供 |
| 永続メモリ | 前日との差分を認識して重複を除去 |
