# ストーリー1：「通知の洪水を制す」
副題 ── 田中慶子と、Slack・Gmail・Notion の三角形 ──

## 登場人物
田中 慶子（たなか けいこ）、34歳。都内IT系スタートアップのプロダクトマネージャー。  
メンバー12名のチームを束ね、朝から晩までSlackとGmailを往復する毎日。  
「大事な通知を見逃した」と叱られた経験から、全通知をONにしていた結果、本末転倒な状態に陥っていた。

## 問題
毎朝Gmailに届くメール：平均87通。Slackのメンション：1日あたり約50件。  
Notionのコメント通知：週100件超。情報の8割は「とりあえずFYI」で、本当に対応が必要なものは1割以下。  
重要なクライアントからのメール返信が埋もれ、対応が翌日になることが月に6〜8回発生していた。

## 出会い
チームのエンジニアが「n8nで通知をフィルタリングしてる」と話しているのを聞いた慶子。  
「ノーコードでもできる？」と聞いたら「UIは全部ビジュアルだよ」と返ってきた。その週末に試してみることにした。

## 実装
```
[Gmail Trigger] 新着メール受信
    ↓
[IF] 件名に"緊急"/"要対応"/"URGENT"を含む
    ↓ YES
[Notion] "要対応ログ"DBにレコード追加（件名・差出人・受信時刻）
    ↓
[Slack] #対応必須チャンネルに通知メッセージ送信
    ↓ NO（スルー）
[Gmail] ラベル"FYI"を付与して自動アーカイブ
```
さらに、Notionのコメント通知は1時間ごとにバッチ集約してSlackへまとめて投稿するフローも追加した。

## 壁
Gmail TriggerがOAuth認証エラーを繰り返す問題が発生。  
「Gmailの接続テスト」をクリックするたびにトークンが失効し、永久ループに陥った。

## 解決
調べるとGoogleのOAuth同意画面で「テストモード」になっていたのが原因だった。  
Googleクラウドコンソールで「本番」に切り替え、スコープに `gmail.modify` を追加したところ、認証が安定した。n8nのコミュニティフォーラムに全く同じ質問と回答が載っており、30分で解決できた。

## 結果
| 指標 | Before | After |
|------|--------|-------|
| 見逃した重要メール（月） | 6〜8件 | 0件 |
| Slack通知の確認時間（日） | 約45分 | 約10分 |
| Notionコメントの確認頻度 | 都度 | 1日2回に集約 |
| 慶子の主観的ストレス | ★★★★★ | ★★☆☆☆ |

## 使ったn8nノード・機能
| ノード/機能 | 用途 |
|-----------|------|
| Gmail Trigger | 新着メール受信トリガー |
| IF | 件名キーワード分岐 |
| Notion | データベースへのレコード追加 |
| Slack | チャンネルへのメッセージ投稿 |
| Schedule Trigger | 1時間ごとのバッチ実行 |
| Gmail（アクション） | ラベル付与・アーカイブ |
