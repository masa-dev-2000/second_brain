# ストーリー5：「領収書の山を倒す」
副題 ── 伊藤雅之と、経費精算の終わらない戦い ──

## 登場人物
伊藤 雅之（いとう まさゆき）、44歳。製造業の経営管理部長。  
社員120名の経費精算・請求書処理を5名の部下と管理している。  
月末の経理締め処理は毎月恒例の残業祭り。「DXしろと言われるが予算がない」と嘆いていた。

## 問題
毎月提出される経費精算書：平均240件。領収書はPDF・JPG・スマホ写真と形式がバラバラ。  
担当者が手動でGoogleフォームのデータと領収書画像を突き合わせ、会計ソフト（freee）に入力していた。  
1件あたりの処理時間：約12分 → 月240件で48時間。入力ミスによる差し戻し：月約18件。  
承認フローも「メールで上長に送って返信待ち」という方法で、未読スルーが月3〜5件発生していた。

## 出会い
freeeのユーザーコミュニティで「n8nとfreee APIを繋いでいる」という記事を読んだ伊藤。  
freeeにはAPI連携機能があることを初めて知り、IT担当者に相談した結果、一緒に構築することになった。

## 実装
```
[Google Forms Trigger] 経費申請フォーム送信
    ↓
[Google Drive] 添付領収書ファイルを取得
    ↓
[HTTP Request] Google Vision API で領収書OCR
    ↓
[Code（JavaScript）] 金額・日付・支払先を
正規表現でテキストから抽出
    ↓
[IF] 申請金額とOCR金額が一致？（±10円以内）
    ↓ YES                ↓ NO
[freee API]          [Gmail/Slack]
支出明細を自動登録    申請者に差し戻し通知
    ↓
[Slack] 上長にSlackで承認リクエスト送信
（承認ボタン付きブロックメッセージ）
    ↓
[Slack Trigger] ボタンクリックを受信
    ↓
[freee API] 承認ステータスを更新
```

## 壁
Slack の「インタラクティブコンポーネント」（ボタン付きメッセージ）はWebhookで応答を受け取る必要があり、n8nのエンドポイントURLを外部公開しなければならなかった。社内セキュリティポリシー上、外部公開は原則NGだった。

## 解決
VPNを経由したリバースプロキシを立て、n8nのWebhookエンドポイントを社内ネットワーク内に閉じたまま、Slack APIからのリクエストのみ許可するIPホワイトリストを設定。セキュリティチームに構成図を提出して承認を得た。

## 結果
| 指標 | Before | After |
|------|--------|-------|
| 月間処理時間（担当者） | 48時間 | 約8時間（確認・例外対応のみ） |
| 差し戻し件数（月） | 18件 | 4件（OCR不一致のみ） |
| 承認スルー件数（月） | 3〜5件 | 0件（Slackボタンで即日応答） |
| freeeへの手入力件数 | 240件 | 0件（全自動） |

## 使ったn8nノード・機能
| ノード/機能 | 用途 |
|-----------|------|
| Google Forms Trigger | 経費申請の受付 |
| Google Drive | 領収書ファイル取得 |
| HTTP Request | Google Vision API OCR呼び出し |
| Code（JavaScript） | 金額・日付の正規表現抽出 |
| IF | 金額一致チェック |
| freee API（HTTP Request） | 支出明細の自動登録・承認 |
| Slack（Block Kit） | 承認ボタン付きメッセージ送信 |
| Webhook Trigger | Slackボタンクリック受信 |
