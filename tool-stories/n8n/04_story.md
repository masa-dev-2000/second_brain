# ストーリー4：「競合を毎朝監視する」
副題 ── 青木隼人と、価格情報収集の泥臭い仕事 ──

## 登場人物
青木 隼人（あおき はやと）、31歳。家電量販チェーンのECサイト運営チームのリーダー。  
担当カテゴリはスマートフォン・タブレット・周辺機器で、取り扱いSKU数は約1,500。  
競合他社（3社）の価格は毎朝8時の朝礼で上長に報告する義務があった。

## 問題
競合3社×主要SKU100品番 = 毎日300URL の価格確認が人力で行われていた。  
アルバイト1名が毎朝6:00から約2時間かけて手動でチェックし、Excelに転記してチームに共有。  
価格変更の検知が遅れ、週1〜2件のタイムラグで「うちが高い」状態が数時間続くことがあった。  
人件費換算で月約6万円、Excelの転記ミスも月に4〜5件発生していた。

## 出会い
エンジニアチームからの提案ではなく、青木自身がn8nのワークフロー共有サイト（n8n.io/workflows）を夜中に眺めていて、スクレイピングテンプレートを発見した。「これ、俺でもできるんじゃないか」と思ったのが始まり。

## 実装
```
[Schedule Trigger] 毎日5:30 AM に起動
    ↓
[Google Sheets] 監視対象URL一覧（300件）を取得
    ↓
[Loop] URLを10件ずつ処理
    ↓
[HTTP Request] 各URLをフェッチ（User-Agent偽装）
    ↓
[HTML Extract] 価格要素を CSS セレクタで抽出
    ↓
[Google Sheets] 前回価格と比較
    ↓
[IF] 価格変動あり（±1%以上）?
    ↓ YES
[Google Sheets] 価格変動ログに記録
    ↓
[Slack] #price-alertチャンネルに
競合名・品番・変動幅を通知
    ↓
[Schedule Trigger] 8:00 AM 朝礼前に
前日からの変動サマリーをSlackで自動投稿
```

## 壁
競合サイトAがCloudflareのBot保護を導入しており、3日目からHTTP Requestが403エラーを返すようになった。スクレイピングが完全にブロックされた。

## 解決
競合サイトAについては公式API（価格比較サイト経由）を使えることが判明したため、HTTP Requestをそちらに切り替え。  
競合BとCについてはリクエスト間隔を `Wait` ノードで3〜7秒のランダム遅延に変更し、かつUser-Agentをローテーションする設定を加えた。利用規約を確認したうえで、1IPにつき1秒1リクエスト以下を遵守している。

## 結果
| 指標 | Before | After |
|------|--------|-------|
| 価格チェック作業時間（日） | 約2時間（アルバイト） | 0分（完全自動） |
| 価格変動の検知速度 | 翌朝（最大24時間後） | リアルタイム（変動直後） |
| 転記ミス（月） | 4〜5件 | 0件 |
| 月間コスト削減 | — | 約6万円の人件費削減 |

## 使ったn8nノード・機能
| ノード/機能 | 用途 |
|-----------|------|
| Schedule Trigger | 定時自動起動（5:30 / 8:00） |
| Google Sheets | URL管理・価格履歴保存 |
| Loop（SplitInBatches） | URLの分割処理 |
| HTTP Request | Webページ・APIのフェッチ |
| HTML Extract | CSSセレクタによる価格抽出 |
| IF | 価格変動の有無判定 |
| Slack | アラート・日次サマリー通知 |
| Wait | リクエスト間隔の制御 |
