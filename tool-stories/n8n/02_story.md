# ストーリー2：「注文が来るたびに走らない」
副題 ── 村上拓海と、手作りEC運営の限界 ──

## 登場人物
村上 拓海（むらかみ たくみ）、29歳。アウトドア用品を扱う小規模ECサイト運営者。  
Shopifyで月間約300〜400件の注文を一人でこなしながら、倉庫管理・顧客対応もすべて担当。  
副業から始めて3年、本業を辞めて独立して1年目。スタッフを雇うほどの余裕はまだない。

## 問題
注文が入るたびにShopify管理画面を開き、手動でGoogleスプレッドシートの在庫表を更新し、Gmailで発送通知メールを書いて送る。  
1件あたり平均8分。月400件だと53時間以上が手作業に消える。  
ピーク時（キャンプシーズン）は深夜まで作業が続き、在庫の二重販売ミスが月2〜3件発生していた。

## 出会い
Xで「n8nでShopify自動化した」という投稿を見た。「セルフホスト可能でタスク数無制限」という一文が刺さった。Zapierは月額が高くて断念していたから。

## 実装
```
[Shopify Trigger] 新規注文イベント
    ↓
[Google Sheets] 在庫マスタシートから該当SKUの在庫数取得
    ↓
[IF] 在庫 >= 1 ?
    ↓ YES
[Google Sheets] 在庫数を -1 に更新
    ↓
[Gmail] 顧客へ注文確認メール送信（テンプレートに注文内容を差し込み）
    ↓
[Slack] #倉庫チャンネルにピッキング指示通知
    ↓ NO（在庫なし）
[Gmail] 顧客へ在庫切れ・キャンセルメール送信
[Shopify] 注文をキャンセル処理
```

## 壁
Google Sheetsの行更新で、在庫数を読んだ直後に別の注文が同時に来ると、在庫数が正しく減らない「競合更新問題」が発生した。月に5〜6回、在庫が-1になるケースが起きた。

## 解決
n8nの「実行を直列化するキュー設定」を有効にして、Shopify Triggerの並列実行数を1に制限。  
さらにSheets読み取り〜書き込みの間に `Wait` ノードでロックをシミュレートするのではなく、Googleスプレッドシートの `ARRAYFORMULA` で集計列を分離し、書き込みを単一セルに限定する設計に変更した。

## 結果
| 指標 | Before | After |
|------|--------|-------|
| 月間手作業時間 | 53時間 | 4時間（例外対応のみ） |
| 在庫ミス（月） | 2〜3件 | 0件 |
| 発送通知メール送信速度 | 手動（最大翌日） | 注文から3分以内 |
| 深夜作業の頻度 | 週3〜4回 | ほぼゼロ |

## 使ったn8nノード・機能
| ノード/機能 | 用途 |
|-----------|------|
| Shopify Trigger | 新規注文イベント検知 |
| Google Sheets | 在庫読み取り・更新 |
| IF | 在庫有無の分岐 |
| Gmail | 確認メール・キャンセルメール送信 |
| Slack | 倉庫スタッフへのピッキング通知 |
| Shopify（アクション） | 注文キャンセル処理 |
| Queue Mode | 並列実行制御（競合防止） |
