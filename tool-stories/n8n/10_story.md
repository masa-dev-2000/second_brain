# ストーリー10：「AIと組んで仕事を変える」
副題 ── 橋本里奈と、Claude APIとの共同作業 ──

## 登場人物
橋本 里奈（はしもと りな）、30歳。マーケティングコンサルタント（フリーランス）。  
複数のクライアント企業から「市場調査レポート」「競合分析レポート」の作成を受注。  
1本のレポートに平均3〜4日かかっており、リサーチとドラフト作成が時間の大半を占めていた。

## 問題
月に8本のレポートを受注するのが限界で、売上は月100〜120万円でキャップしていた。  
リサーチ（Webで複数ソース読み込み）に1本あたり平均10時間、ドラフト作成に8時間、構成整理・校正に6時間かかっていた。  
「調べれば調べるほどAIに任せられることが増えているはずなのに、まだ全部自分でやっている」という違和感があった。

## 出会い
n8nのブログ記事「Build AI Agents with n8n」を読み、「AI エージェントがWebリサーチを自動でやってくれる」という事例を見た。Claude の 200K コンテキストウィンドウなら長文ドキュメントも一度に処理できると知り、構想を練り始めた。

## 実装
```
【レポート自動生成パイプライン】

[Webhook Trigger / Notion Trigger]
クライアントからの調査依頼入力を受信
（テーマ・対象市場・競合リスト・納期）
    ↓
[HTTP Request × 5] 並列Webリサーチ
    - Google Search API（Custom Search JSON）
    - 業界ニュースサイトRSSフィード
    - 競合企業公式サイト
    - 有価証券報告書（EDINET API）
    - SNSトレンド（X API）
    ↓
[Code（JavaScript）] 取得したHTML/JSONを
プレーンテキストに変換・トークン数を推計
    ↓
[Anthropic Claude] プロンプト：
    「以下の資料を分析して、[テーマ]に関する
    市場調査レポートの骨子（章立て・各章の
    キーポイント3点）をJSON形式で出力してください」
    ↓
[Loop] 各章を順次処理
    ↓
[Anthropic Claude] 各章の本文を2,000字程度で生成
（前章の要約をコンテキストとして引き継ぐ）
    ↓
[Google Docs] 生成したテキストを章ごとに追記
    ↓
[Anthropic Claude] レポート全体の最終校正：
    「矛盾点・重複・表現の不統一を修正し
    エグゼクティブサマリーを冒頭に追加してください」
    ↓
[Google Docs] 最終版として保存
    ↓
[Gmail] クライアントへ「ドラフト完成」通知
    ↓
[Notion] プロジェクト管理DBのステータスを"レビュー待ち"に更新
```

## 壁
Claude APIへの連続呼び出しで、章ごとに独立したコンテキストになるため、後半の章が前半の内容を踏まえずに書かれ、レポート全体の一貫性が失われるという品質問題が発生した。第3章以降に「第1章で述べたように」という記述がまったく現れず、それぞれが単独記事のような仕上がりになった。

## 解決
各章の生成時に「前章までの要約（約500字）」を毎回システムプロンプトに含める仕組みを実装。`Code（JavaScript）` ノードで前章の生成テキストを要約APIに通してから次章プロンプトに注入する「コンテキストアキュムレーター」パターンを自作した。加えてClaude の Extended Thinking 機能を骨子生成フェーズに使うことで、章立ての論理的一貫性が大幅に改善した。

## 結果
| 指標 | Before | After |
|------|--------|-------|
| レポート1本の作業時間 | 24時間（3日） | 約4時間（レビュー・修正のみ） |
| 月間受注可能本数 | 8本 | 20本（上限は里奈のレビュー時間） |
| 月間売上（想定） | 約100万円 | 約240万円 |
| リサーチのカバー範囲 | 3〜5ソース | 常時10〜15ソース |

## 使ったn8nノード・機能
| ノード/機能 | 用途 |
|-----------|------|
| Webhook Trigger / Notion Trigger | 調査依頼の受付 |
| HTTP Request（並列） | マルチソースWebリサーチ |
| Code（JavaScript） | HTML→テキスト変換・コンテキスト蓄積 |
| Anthropic（Claude） | 骨子生成・章本文生成・最終校正 |
| Loop（SplitInBatches） | 章ごとの順次生成処理 |
| Google Docs | レポートドキュメントの作成・更新 |
| Gmail | クライアントへの完成通知 |
| Notion | プロジェクト管理・ステータス更新 |
| AI Agent（LangChain） | Extended Thinkingによる骨子検討 |
