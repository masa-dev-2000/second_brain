# ストーリー6：「SNSを自動操縦する」
副題 ── 松田さくらと、コンテンツ量産の仕組み化 ──

## 登場人物
松田 さくら（まつだ さくら）、26歳。コスメブランドのSNSマーケター。  
Instagram・X（旧Twitter）・TikTokの3媒体を担当し、週に合計21本の投稿が求められる。  
「クリエイティブに集中したいのに、投稿作業と分析で時間が飛んでいく」が口癖。

## 問題
週21本の投稿のうち、実際のコンテンツ制作に使える時間はわずか30%。  
残り70%は「投稿のスケジューリング」「各媒体のエンゲージメント集計」「週次レポートのExcel作成」に消えていた。  
Instagramのインサイト数値をCSVでダウンロードし、XのアナリティクスCSVと突き合わせてPowerPointに貼り付ける作業だけで毎週3時間かかっていた。

## 出会い
フォローしているマーケターのXで「n8nとBuffer APIを連携させて投稿自動化した」という投稿を見た。「Bufferって外部ツールからも動かせるんだ」と気づいたのが転換点。

## 実装
```
【投稿スケジューリングフロー】
[Notion Trigger] コンテンツカレンダーDBのステータスが
"承認済み"に変わったら起動
    ↓
[Notion] 投稿テキスト・画像URL・媒体・投稿日時を取得
    ↓
[Switch] 媒体で分岐（Instagram / X / TikTok）
    ↓
各媒体のAPI（Buffer）に投稿をスケジュール登録
    ↓
[Notion] ステータスを"スケジュール済み"に更新

【週次分析レポートフロー】
[Schedule Trigger] 毎週月曜9:00
    ↓
[HTTP Request] Instagram Graph API → エンゲージメント取得
[HTTP Request] X API v2 → ツイート分析取得（並列）
    ↓
[Merge] 全媒体のデータを統合
    ↓
[Google Sheets] レポートシートに自動書き込み
    ↓
[OpenAI] 「先週の投稿パフォーマンスを分析し
改善提案を3点挙げてください」
    ↓
[Slack] #マーケチームに週次レポートとAI改善提案を投稿
```

## 壁
TikTokのAPIは個人/中小企業向けの投稿APIが非常に制限が多く、Buffer経由でもTikTok連携が不安定で、投稿が失敗しても通知が来ないサイレント失敗が続発した。

## 解決
TikTokへの自動投稿は諦め、「TikTok用コンテンツ準備完了通知」に用途を変更。n8nがコンテンツをGoogleドライブに置き、Slackで「今日の15:00にこの動画を投稿してください」と担当者に通知する半自動フローに切り替えた。TikTok以外の2媒体は完全自動のままで運用継続。

## 結果
| 指標 | Before | After |
|------|--------|-------|
| 投稿スケジューリング作業（週） | 約4時間 | 約20分（承認のみ） |
| 週次レポート作成時間 | 約3時間 | 0分（自動生成） |
| コンテンツ制作時間の割合 | 30% | 65%に増加 |
| 投稿忘れ・遅延 | 月3〜4件 | 0件 |

## 使ったn8nノード・機能
| ノード/機能 | 用途 |
|-----------|------|
| Notion Trigger | コンテンツ承認の検知 |
| Notion | 投稿内容・スケジュールの取得・更新 |
| Switch | 媒体別の分岐処理 |
| HTTP Request（Buffer API） | 投稿スケジューリング |
| HTTP Request（Instagram/X API） | エンゲージメントデータ取得 |
| Merge | 複数媒体データの統合 |
| Google Sheets | レポートデータ書き込み |
| OpenAI | パフォーマンス分析・改善提案 |
| Schedule Trigger | 週次レポートの定時実行 |
| Slack | チームへの通知・レポート共有 |
