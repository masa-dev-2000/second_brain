# ストーリー9：「採用の目利きをAIに」
副題 ── 松本さんと書類選考600枚の格闘 ──

## 登場人物
松本 奈々（36歳）。IT系スタートアップの人事責任者（HR Mgr）。全社員50名のスタートアップで一人採用担当として、エンジニア・デザイナー・営業など複数職種を同時に採用している。採用広告を出すたびに「嬉しい悲鳴」の応募が来るが、一人でさばくには限界だった。

## 問題
直近の募集（エンジニア3名）で600件の応募書類が集まった。書類選考の基準は職種ごとに異なり、各選考には「スキルセットの合致」「カルチャーフィット文章」「成長意欲の記述」など複数の評価軸があった。600件を一人でスクリーニングするのに2週間かかり、優秀な候補者が他社に流れてしまう事態が発生。応募から一次連絡まで平均12日かかっていた。

## 出会い
HRテックコミュニティの勉強会で「Difyで採用スクリーニングを半自動化している会社がある」と聞いた。「評価に偏りが出ないか」「公平性は守れるか」を気にしながらも、「AIはスクリーニングの補助で、決定はあくまで人間」という使い方なら問題ないと判断した。

## 実装
1. **Webhookトリガー**：採用管理ツール（Greenhouse）から応募書類が提出されるたびにDifyにデータ送信。
2. **Document Extractor**：履歴書・職務経歴書PDFからテキスト抽出。
3. **Knowledge Baseノード**：職種別の採用基準定義書・過去の採用成功例と失敗例の特徴まとめをRAGで登録。
4. **LLMノード（スキル評価）**：職種のMust/Wantスキルリストと照合して「スキル合致スコア（0〜10）」と根拠を生成。
5. **LLMノード（カルチャーフィット）**：志望動機・自己PRの文章からカルチャーフィットに関わる表現を抽出・評価。
6. **Codeノード**：2つの評価スコアを集計し、段階判定（S/A/B/C）に変換。
7. **HTTP Requestノード**：評価結果をGreenhouseの候補者プロフィールに自動タグ付け・コメント追加。

## 壁
LLMが「海外大学出身」「大手企業経験者」を暗黙的に高評価するバイアスが評価文章に表れていた。「一流大出身で○○社での実績は評価に値する」という表現がカルチャーフィット評価に混入していた。バックグラウンドによる差別につながりかねないと松本さんが気づいた。

## 解決
プロンプトに「出身大学・出身企業・年齢・性別・国籍・家族構成に関する記述は評価に使用しないこと」を明記し、それらの情報をDocument Extractor後のマスキングノード（Codeノード）で除去してからLLMに渡すフローに変更した。評価軸を「経験の具体性」「スキルの合致度」「成長意欲の記述」のみに限定した。

## 結果
| 指標 | Before | After |
|------|--------|-------|
| 応募から一次連絡まで | 平均12日 | 平均3日 |
| 書類選考1件あたりの時間 | 約12分 | 3分（AIレポート確認のみ） |
| 書類選考通過候補者の内定率 | 22% | 38%（質が向上） |
| 松本さんの選考週の残業時間 | 週25時間超 | 週8時間程度 |

## 使ったDify機能
| ノード/機能 | 用途 |
|------------|------|
| Webhookトリガー | Greenhouseからの応募データ受信 |
| Document Extractor | 履歴書・職務経歴書のテキスト抽出 |
| Codeノード | 個人情報マスキング・スコア集計 |
| Knowledge Base（RAG） | 採用基準・成功失敗パターン参照 |
| LLMノード（×2） | スキル評価・カルチャーフィット評価 |
| HTTP Requestノード | Greenhouseへの評価結果自動記入 |
