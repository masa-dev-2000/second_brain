# ストーリー2：「問診票AI処理」
副題 ── 佐藤院長と受付スタッフの残業問題 ──

## 登場人物
佐藤 由美子（38歳）。東京郊外の内科・小児科クリニックの院長。開業5年目で患者数は順調に増えたものの、受付スタッフ3名が毎日30分以上の残業をしている現状に頭を悩ませていた。患者さんに丁寧に向き合いたいという想いとは裏腹に、事務処理に追われる日々だった。

## 問題
1日平均80名の患者が来院するクリニックで、紙の問診票を受付スタッフが手入力でカルテシステムに転記していた。転記作業は1枚あたり約5分。誤字・読み間違いによるミスが月に約15件発生しており、医師への申し送り漏れも問題になっていた。特に初診患者の問診票は項目が多く、混雑時は待ち時間が30分を超えることもあった。

## 出会い
勉強会で知り合ったIT企業の医療担当エンジニアから「タブレット問診とDifyを組み合わせると転記ゼロにできますよ」と聞いた。非エンジニアの院長でも設定できるという話に「半信半疑ながら試してみた」。

## 実装
1. **Webhookトリガー**：タブレット問診アプリからフォーム送信されたJSONデータをDifyのWorkflowへ送信。
2. **LLMノード**：受け取った問診データを構造化し、主訴・既往歴・アレルギーを要約した「医師向けサマリー」を生成。
3. **IF/ELSEノード**：「発熱38度以上」「アレルギーあり」「小児科希望」などの条件分岐で診察室・担当医師を自動振り分け。
4. **HTTP Requestノード**：要約データをカルテシステムのAPIへ自動転記。同時にSlackの診察室チャンネルへ患者情報を通知。
5. **Knowledge Baseノード**：よくある症状と対応フローをRAGで参照し、感染症疑いの際は院内感染対策メモを自動付与。

## 壁
LLMノードの要約が時々過剰に医学的解釈を加えてしまい、「腹痛」と書いた患者に「虫垂炎の可能性」などの推測コメントが入った状態でカルテ転記されてしまった。スタッフが困惑し、「AIが診断している」と患者にクレームが入りかけた。

## 解決
LLMのプロンプトに「患者の入力内容をそのまま整理するだけにし、医学的診断・推測は絶対に加えないこと」という制約を明記。さらにOutputスキーマを固定して、サマリーの構造を「主訴：〇〇」「症状の開始時期：〇〇」のテンプレート形式に限定した。

## 結果
| 指標 | Before | After |
|------|--------|-------|
| 問診票1件の処理時間 | 約5分（手入力） | 約20秒（自動） |
| 転記ミス件数 | 月15件 | 月0〜1件 |
| 受付スタッフ残業時間 | 月平均30分/日 | 月平均5分/日 |
| 患者待ち時間（混雑時） | 最大30分以上 | 最大12分程度 |

## 使ったDify機能
| ノード/機能 | 用途 |
|------------|------|
| Webhookトリガー | タブレット問診アプリからのデータ受信 |
| LLMノード | 問診データの構造化サマリー生成 |
| IF/ELSEノード | 症状・年齢による診察室振り分け |
| HTTP Requestノード | カルテシステムAPIへの自動転記 |
| Knowledge Base | 感染症対応フロー・院内ガイドライン参照 |
