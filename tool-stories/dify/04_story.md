# ストーリー4：「学習コンテンツ自動生成」
副題 ── 山田先生とオンライン教材の量産作戦 ──

## 登場人物
山田 浩二（45歳）。私立高校の理科教師で、コロナ禍を機に始めたオンライン学習サービスを副業で運営している。物理・化学の動画教材を自作しているが、テスト問題やワークシートの制作が追いつかず、年間50本の教材動画に対して練習問題は20セットしか作れていなかった。

## 問題
オンライン学習サービスの登録生徒数は2年で180名に増えたが、コンテンツの充実が追いつかなかった。1セットの練習問題（10問＋解説）を作るのに平均3時間かかり、月8時間しか割けない山田先生には限界だった。生徒アンケートでは「演習問題が少ない」が不満1位で、退会理由の35%を占めていた。

## 出会い
教育テック系のSlackコミュニティで「Difyで問題自動生成している先生がいる」という書き込みを発見。「AIが作った問題は質が低い」という先入観を持ちつつも、「たたき台を作るだけでも楽になる」と試してみた。

## 実装
1. **Workflow（フォームトリガー）**：「単元名」「難易度（基礎/標準/応用）」「問題数」「問題形式（選択/記述/計算）」を入力するフォームを作成。
2. **Knowledge Baseノード**：学習指導要領・教科書の重要概念リスト・過去の模試問題パターンをRAGで登録。
3. **LLMノード（問題生成）**：単元・難易度・形式を指定して問題文を生成。
4. **LLMノード（解説生成）**：生成した問題ごとに「解き方のヒント」「解答」「よくある間違いパターン」を生成。
5. **Iterationノード**：指定した問題数分ループして問題と解説のセットを生成。
6. **Codeノード**：生成結果をGoogle Docsに貼り付けやすいMarkdown形式でフォーマット出力。

## 壁
物理の計算問題で、LLMが問題の数値と解答の計算結果が合わない問題を生成してしまった。たとえば「質量5kgの物体に10Nの力を加えたときの加速度は？」という問題なのに、解説で「加速度 = 2 m/s²」と誤った値を出力するケースが複数発生した。

## 解決
Codeノードを追加し、計算問題については「数値・単位・答え」をPythonコードで検証するステップを組み込んだ。計算結果が一致しない場合はLLMに再生成を指示するループ（最大3回リトライ）を設けた。理論・概念問題はこの検証ノードをスキップする分岐もIF/ELSEで実装。

## 結果
| 指標 | Before | After |
|------|--------|-------|
| 問題セット制作時間 | 3時間/セット | 25分/セット（人間の確認込み） |
| 月間制作可能セット数 | 約3セット | 約18セット |
| 生徒満足度「演習量」 | 不満1位 | 満足上位3位に改善 |
| 退会率（演習不足理由） | 35% | 12%に改善 |

## 使ったDify機能
| ノード/機能 | 用途 |
|------------|------|
| Workflowフォームトリガー | 単元・難易度・形式の入力UI |
| Knowledge Base（RAG） | 学習指導要領・問題パターン参照 |
| LLMノード（×2） | 問題生成・解説生成 |
| Iterationノード | 指定問題数のループ生成 |
| Codeノード | 計算検証・Markdownフォーマット出力 |
| IF/ELSEノード | 計算問題と概念問題の分岐処理 |
