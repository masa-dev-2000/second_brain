## 概要

AIコーディングエージェントにソフトウェア開発の全フェーズ（要件確認→計画→TDD実装→コードレビュー→PR作成）を強制するフレームワーク。Claude Code・GitHub Copilot CLI・Cursor・Gemini CLI等、主要な全AIツールに対応。

「コードを書く前に考えさせる」ことで、手戻りを防ぎ、品質の高い成果物を一発で得ることを目的とする。

---

## 7段階ワークフロー

| フェーズ | 内容 |
|---------|------|
| 1. ブレインストーミング | エージェントが要件の不明点を質問、設計の選択肢を提示 |
| 2. Gitワークツリー | 隔離された作業ブランチを作成、テスト実行ベースラインを確立 |
| 3. 計画 | 2〜5分単位のタスクに分割、ファイルパスと検証手順を明記 |
| 4. 実装 | サブエージェントへの並列ディスパッチまたはバッチ実行 |
| 5. TDD | RED（失敗テスト）→GREEN（実装）→REFACTOR サイクルを強制 |
| 6. コードレビュー | 計画に対する実装の一致を自動確認 |
| 7. ブランチ完了 | マージまたはPR作成、クリーンアップ |

---

## あるとないとの違い

| 観点 | ない場合（素のAIエージェント） | ある場合 |
|------|-------------------------------|---------|
| 要件確認 | いきなりコードを書き始める | 「どんな認証方式？OAuth？パスワード？」と確認 |
| テスト | 「テストも書きました」（品質不明） | RED→GREEN→REFACTORサイクルを強制 |
| 完了の定義 | 曖昧 | 計画に記述した検証ステップで合否を判定 |
| 大規模タスク | 途中で迷子になる | 2〜5分タスクに分割して逐次実行 |
| コードレビュー | なし | 実装後に計画との差異を自動チェック |

## 環境構築方法

### 前提条件
- Claude Code / GitHub Copilot CLI / Cursor / Gemini CLI のいずれか
- Git 2.30以上（worktree機能使用のため）

### インストール手順
```bash
# Claude Codeにプラグインとしてインストール
/plugin install superpowers@claude-plugins-official

# またはCLI経由
npx skills add obra/superpowers

# または手動（CLAUDE.mdに直接組み込む）
curl -fsSL https://raw.githubusercontent.com/obra/superpowers/main/CLAUDE.md >> CLAUDE.md
```

### 他ツールへの適用
```bash
# Cursor
cp ~/.obra/superpowers/.cursorrules .cursorrules

# GitHub Copilot CLI
gh copilot skill add superpowers

# Gemini CLI
cp ~/.obra/superpowers/GEMINI.md .gemini/
```

### 動作確認
```bash
# Claude Codeで試す
claude "新しい機能を追加したい"
→ スーパーパワーが有効なら、まず「どんな機能ですか？何を達成したいですか？」と質問が来る
```

## ベストプラクティス

1. **ブレインストーミングフェーズを省略しない:**
```
# NG: 急いで実装させる
"さっさとコード書いて"

# OK: フェーズを尊重する
"ユーザーのCSVエクスポート機能を実装したい。まず要件を整理しよう"
→ エージェントが「フォーマット・文字コード・列の選択は？」と確認
```

2. **タスク分割の細かさを調整する:**
```
# 大きすぎるタスクは「もっと細かく」と指示
"1タスクを最大15分以内にして再計画して"
```

3. **並列サブエージェントを活用:**
```
"フロントエンドとバックエンドは依存関係がないので並列で実装して"
→ 2つのサブエージェントが同時作業 → 時間が半分に
```

4. **TDDを厳守させる:**
```
"必ずRED→GREEN→REFACTORの順で。テストが先、実装が後"
```

5. **計画をドキュメントとして保存:**
```bash
# エージェントが生成した計画を保存
/save-plan docs/sprint-plan-2026-05-22.md
```

## セキュリティ観点

### Gitワークツリーのメリット
- 隔離された環境で作業するため、本番ブランチに誤ってプッシュするリスクが低下
- 作業結果が気に入らなければワークツリーごと削除できる

### 確認すべき事項
- エージェントが計画フェーズで外部APIキーや機密設定を要求する場合は手動で提供する（プロンプトに直接書かない）
- PR作成の自動化は慎重に：組織の承認フローをバイパスしないよう設定する

```bash
# PR作成の自動化を無効化（手動でプッシュする場合）
# superpowers の設定で
auto_pr: false
```

## ペルソナ設定と使い方

### ペルソナ：松田 健一（35歳・スタートアップCTO・5人チームのテックリード）

松田さんのチームはAIエージェントを使って機能開発をしているが、「AIが一気に大量のコードを書いて、レビューが追いつかない」「テストのないコードが増えてきた」という問題が出てきていた。

#### superpowers導入後の変化

```bash
# 以前の典型的なやり取り
claude "ユーザーダッシュボードを作って"
→ 1000行のコードが一気に生成、テストなし、レビューに2時間

# superpowers導入後
claude "ユーザーダッシュボードを作りたい"

# フェーズ1: ブレインストーミング
→ "どんな指標を表示する？リアルタイム更新は必要？権限はある？"
松田: "月次の売上・ユーザー数・チャーン率。管理者のみ閲覧可。リアルタイム不要"

# フェーズ2-3: 計画
→ タスクリストが生成：
  - Task 1: 認証ミドルウェアのadmin_requiredを追加（15min）
  - Task 2: ダッシュボードコントローラーを作成（10min）
  - Task 3: 売上集計クエリを実装（20min）
  ...

# フェーズ4-5: TDD実装
→ 各タスクでテストを書いてからコード実装

# フェーズ6: コードレビュー
→ "タスク3の売上集計でN+1クエリが発生している。修正してよいか？"

# 1ヶ月後の効果：
# - PR平均レビュー時間: 2時間 → 30分
# - テストカバレッジ: 42% → 78%
# - バグ発生率: -60%
```
