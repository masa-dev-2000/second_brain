## 概要

$8〜9のESP32マイコンで既存WiFiの電波（CSI: Channel State Information）を解析し、**カメラ・ウェアラブル不要・壁越し**で人の存在・呼吸・心拍・17キーポイントの姿勢推定・転倒検知を行うシステム。

エッジAIモデルがリアルタイムで処理し、プライバシーに完全配慮した空間インテリジェンスを既存WiFiインフラを活用して実現する。

|------|-----------|

## 環境構築方法

### 前提条件
- ESP32開発ボード（WROOM-32またはS3推奨）
- WiFiルーター（802.11n以上）
- Python 3.10以上（ダッシュボードサーバー用）
- はんだ付けスキル不要（開発ボードをそのまま使用）

### ハードウェアのセットアップ
```bash
# 1. ESP32ファームウェアの書き込み
git clone https://github.com/ruvnet/RuView
cd RuView/firmware

# Arduino IDEまたはPlatformIOで書き込み
# boards/esp32-wroom32/ のファームウェアを選択
pio run --target upload

# または提供のバイナリをフラッシュ
esptool.py write_flash 0x0 firmware_esp32.bin
```

### ネットワーク設定
```bash
# ESP32にWiFi接続先を設定
# firmware/config.h を編集
#define WIFI_SSID "YourSSID"
#define WIFI_PASSWORD "YourPassword"
#define SERVER_URL "http://192.168.1.100:5000"  # ダッシュボードサーバーのIP
```

### サーバーのセットアップ
```bash
# ダッシュボードサーバーをインストール
cd RuView/server
pip install -r requirements.txt

# 設定
cp config.example.yaml config.yaml
# → デバイスIPアドレス・アラート設定等を編集

# 起動
python server.py
# → http://localhost:5000 でダッシュボードにアクセス
```

### 設置場所の選定
```
推奨設置場所:
- WiFiルーターの隣（送信機として機能）
- 部屋の対角線上（受信機として）
- 高さ1〜1.5m（人体への感度が最適）

NGな設置場所:
- 金属の壁・扉の隣（電波が遮断される）
- 水槽・水回りの近く（水は電波を吸収）
```

### 動作確認
```bash
# ダッシュボードで確認
# → 「存在: 1名検知」が表示されれば成功
# 息を深く吸ったり吐いたりして呼吸数が変化するかを確認
```

## ベストプラクティス

1. **キャリブレーションを必ず行う:**
```bash
# 空室状態でベースラインを取得
curl -X POST http://localhost:5000/api/calibrate
# → 誤検知が大幅に減少
```

2. **複数ESP32で精度を向上:**
```yaml
# config.yaml
devices:
  - id: esp32_01
    role: transmitter
    location: "northeast_corner"
  - id: esp32_02
    role: receiver
    location: "southwest_corner"
# → 送受信ペアで感度・精度が向上
```

3. **アラートの設定:**
```yaml
alerts:
  fall_detected:
    enabled: true
    channels: [slack, email, sms]
    delay_seconds: 5  # 誤検知防止のため5秒待ってから送信
  
  no_motion:
    enabled: true
    threshold_minutes: 30  # 30分動きがなければアラート
    only_during: "08:00-22:00"
```

4. **データのプライバシー管理:**
```yaml
privacy:
  store_raw_csi: false      # 生のCSIデータは保存しない
  store_events_only: true   # 検知イベントのみ保存
  retention_days: 30        # 30日後に自動削除
```

## セキュリティ観点

### プライバシーの設計原則
- **カメラレス設計:** 個人の画像・映像は一切生成されない
- **識別不可能な生体データ:** 呼吸・心拍の波形から個人を特定することは困難
- GDPRの「special category data（健康データ）」に該当する可能性があるため、EU内での使用は法律専門家に確認を推奨

### 電波規制
```
日本では:
- WiFi帯域（2.4GHz/5GHz）の使用は問題なし
- ESP32の送信出力は技術適合証明（技適）が必要
  → 技適マーク付きのESP32モジュールを使用すること
```

### データの暗号化
```yaml
# サーバー設定でデータを暗号化
encryption:
  at_rest: true
  key_rotation_days: 90
```

### 同意の取得
- 施設でRuViewを使用する場合、在室者に対して「WiFiセンシングを実施しています」という告知と同意取得が必要（施設の種類・国によって異なる）

## ペルソナ設定と使い方

### ペルソナ：木村 敦（54歳・介護施設運営者・施設利用者は平均82歳）

木村さんは施設の入居者の夜間転倒事故が年3件発生し、解決策を模索していた。カメラは「プライバシーが…」と家族から反対、ウェアラブルは「本人が外してしまう」という問題があった。

```bash
# 各居室のWiFiアクセスポイント横にESP32を設置（1部屋$8）
# 施設全体（20部屋）で$160+設置工事費

# サーバーはナースステーションのPC上で動作

# 夜中2時（スタッフのスマホに通知）
「301号室: 転倒の可能性を検知しました。呼吸に変化があります。確認を推奨」

# 翌朝のダッシュボードで全居室の夜間状況を一覧確認
「302号室: 昨夜の平均呼吸数18回/分（正常範囲）」
「303号室: 昨夜2時15分に一時的な動作あり、3分後に安定」

# 3ヶ月後の効果:
# - 転倒事故: 年3件 → 0件（早期検知で防止）
# - 夜間巡回の効率化: 全部屋定期巡回→異常時のみ対応
# - 家族からの「プライバシーを守れている」という信頼獲得
```
